# Analysis (Pandas First)

This folder contains the first-pass analysis workflow for DiceLab benchmark data using pandas.

## Why pandas first?

- Familiar, industry-standard dataframe tooling
- Excellent for reproducible tabular transformations
- Easy handoff into notebooks, scripts, and Streamlit later

## Inputs

- `benchmarks/results/benchmark_report.json`

## Module Structure

| File | Role |
|---|---|
| `build_tables.py` | Core transformation library — loads the benchmark JSON and normalises it into the three canonical DataFrames (`run_table`, `batch_table`, `metadata_table`). Importable from scripts, notebooks, and a future Streamlit dashboard. |
| `run_analysis.py` | Stage 1 CLI driver — calls `build_tables`, exports CSVs to `shared-data/`, and writes the markdown summary to `reports/`. |
| `analyze_tables.py` | Analysis and visualization library — loads the canonical CSVs and exposes Plotly chart functions for within-language scaling, trial distributions, cross-language comparisons, consistency (CV), and macro batch trends. Returns `plotly.graph_objects.Figure` objects compatible with both HTML export and Streamlit. |
| `build_report.py` | Stage 2 HTML report builder — prepares data contexts and renders Jinja2 templates into a self-contained, single-file HTML report with embedded CSS/JS and Plotly charts. Writes to `reports/benchmark_report.html`. |
| `run_analytic_pipeline.py` | **Pipeline orchestrator** — runs both stages in sequence. The recommended entry point for producing all outputs from a single command. |

### Templates (`analysis/templates/`)

The HTML for the report is maintained as Jinja2 templates, separate from the Python data logic:

| File | Role |
|---|---|
| `base.html` | Document shell — `<!DOCTYPE>`, `<head>` with inlined CSS/JS/Plotly, `<body>` wrapper. Uses `{% include %}` to pull in each section. |
| `macros.html` | Reusable components — `insight_card`, `insight_row`, `chart_tip`, `author_note`, `dropdown`, `stats_table`. Imported by section templates. |
| `intro.html` | Section 1: Welcome — static prose, AI disclaimer, author placeholder. |
| `methodology.html` | Section 2: Methodology — collapsible data-pipeline walkthrough. |
| `batch.html` | Section 3: Batch Timing — trend chart, insight cards, data-driven prose. |
| `cross_language.html` | Section 4: Cross-Language Comparison — scaling, bar, ridgeline, CV charts with dropdown navigation. |
| `per_language.html` | Section 5: Per-Language Scaling — nested dropdowns for language and workload histograms. |

### Author's Notes (`analysis/author_notes.yaml`)

The report includes "Author's take" callout boxes where you can add personal
commentary.  These are **not** hard-coded in the templates — they're loaded
from an external YAML file that is git-ignored so your notes stay local.

| File | Committed? | Purpose |
|---|---|---|
| `author_notes.example.yaml` | Yes | Documents the expected schema with placeholder text. |
| `author_notes.yaml` | No (`.gitignore`d) | Your working copy — fill in real observations here. |

**Getting started:**

```bash
cp analysis/author_notes.example.yaml analysis/author_notes.yaml
```

Then edit `author_notes.yaml` with your observations.  The keys are:

- `intro` — personal intro for the Welcome section
- `batch` — observations on batch-to-batch stability
- `cross_language` — cross-language comparison analysis
- `per_language.<lang>` — per-language notes (`cpp`, `go`, `java`, `python`, `rust`)

If the file is missing or a key is absent, the template renders built-in
placeholder text automatically — the report always builds successfully.

## Outputs

Generated by `analysis/run_analysis.py`:

- `shared-data/analysis_run_table.csv`
- `shared-data/analysis_batch_table.csv`
- `shared-data/analysis_language_workload_summary.csv`
- `reports/analysis_summary.md`

Generated by `analysis/build_report.py`:

- `reports/benchmark_report.html`

## Run

### Full pipeline (recommended)

From repo root:

```bash
python analysis/run_analytic_pipeline.py
```

This runs both stages in sequence and writes all outputs listed above.

Optional flags:

```bash
python analysis/run_analytic_pipeline.py \
    --input benchmarks/results/benchmark_report.json \
    --shared-data shared-data \
    --reports reports
```

To run a single stage:

```bash
python analysis/run_analytic_pipeline.py --stage analysis
python analysis/run_analytic_pipeline.py --stage report
```

### Individual stages

Each stage script remains independently runnable:

```bash
python analysis/run_analysis.py
python analysis/build_report.py
```

## Notes

- This is a scripted data preparation baseline, not a dashboard.
- The data model is intentionally reusable for future Streamlit/report layers.
