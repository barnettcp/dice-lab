2. Methodology

Understanding how the data was collected is just as important as the results themselves. This section walks through the benchmark design, the tooling, and the analysis pipeline so you can judge the results on their merits. The data that is being collected is quite simple, but the process of cleanly capturing it, structuring it, analyzing it, and presenting it is complex. As a project's data increases in complexity, understanding these downstream steps become critical to a successful analysis.

Benchmark design & data pipeline
  1. Implementation. The same dice simulation was coded in five languages (C++, Go, Java, Python, Rust), each following a shared functional spec. Every implementation accepts the same CLI contract: number of rolls, number of sides, and an optional seed.
  2. Build configuration. Compiled languages use optimised release builds (e.g. -O3 for C++, cargo build --release for Rust). Python runs on the standard CPython interpreter with no special flags.
  3. Benchmark execution. The orchestrator (benchmarks/benchmark_runner.py) runs {{ meth.n_batches }} batch runs. In each batch, every language is exercised at {{ meth.n_workloads }} workload levels (100, 1 K, 10 K, 100 K, 1 M rolls) for {{ meth.trials_per }} trials each. Timing captures only the roll loop, excluding process start-up and I/O overhead where possible.
  4. Raw output. The runner writes a structured JSON report to benchmarks/results/benchmark_report.json containing per-trial timings, batch metadata, and environment info.
  5. Analysis pipeline. Running python analysis/run_export.py normalises the JSON into three canonical CSV tables under shared-data/:
    • Run table — {{ meth.n_rows }} rows, one per timed trial (the most granular view).
    • Batch table — {{ meth.n_batches }} rows, one per full benchmark batch.
    • Workload summary — pre-aggregated mean, median, std, min, max per (language, workload) pair.
  6. Report generation. This HTML report is built from those CSVs by python analysis/run_report.py. Charts are Plotly figures; prose and stats are computed at build time.
